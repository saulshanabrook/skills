## Main Artifact Shape

For RFCs/specs, decide whether the main body is:

- architecture/design review;
- normative reference spec;
- migration plan;
- implementation brief;
- research ledger.

If the user wants architecture/design review, write the architecture first and keep evidence matrices, KU classifications, and hole ledgers as appendices or companion notes.

## Stop Conditions

Stop and ask before proceeding if:

- A normative claim lacks primary project evidence.
- A proposed refactor changes scope or grants implementation permission.
- A knowledge unit is blocked by a product or safety decision.
- The document needs code changes to become truthful.
- The refactor would leave the main artifact less understandable than the source document.
